# results

`raw/<run_id>/` holds one serving configuration's run. It is written only by `slurm/sweep.sbatch` and never edited by hand.

Before commit, `scripts/pack_results.sh` gzips the request logs and server logs (`raw_*.jsonl.gz`, `vllm.log.gz`; the analysis reads them directly) and replaces site-specific identifiers, such as the node-local scratch path, with `<redacted>`. No measured value is touched. A run with no `summary.csv` is a failed attempt, kept as a record; its cause is in `docs/notes.md`.

A run id containing `-knee-` adds concurrency levels to an existing configuration. `analysis/cost.py` merges it; where a level was measured twice, the first run is reported and both go to `tables/anchor_repeats.csv`.

| File | Content |
|---|---|
| `tables/cost_per_level.csv` | Per configuration, workload and concurrency: latency, throughput, board power, list-price cost, API cost of the same requests |
| `tables/monthly_breakeven.csv` | Capacity within the SLO, monthly rent, break-even volume, and whether self-hosting can win |
| `figures/*.png` | `analysis/figures.py`, from the tables only |

| File | Content |
|---|---|
| `job.txt` | Start time, model and revision, download and startup durations, completion status |
| `config.yaml` | The exact configuration: image, tensor parallelism, engine arguments, workloads |
| `run.json` | Provenance: git SHA, Slurm job id, GPUs, driver, CUDA, engine version, config |
| `raw_<workload>.jsonl` | One line per request (schema below), warm-up included and marked |
| `power.csv` | `nvidia-smi` power, utilization and memory, every second |
| `metrics_after_<workload>.prom` | The engine's Prometheus counters after each workload |
| `summary.csv`, `summary_per_rep.csv` | Generated by `bench/summarize.py` |

## Request record

| Field | Meaning |
|---|---|
| `run_id`, `label`, `concurrency`, `rep`, `seq`, `worker`, `prompt_id`, `warmup` | Identity. `warmup: true` lines are excluded from statistics. |
| `t_wall` | Unix time the request was sent |
| `ttft_s`, `ttft_content_s` | Time to the first streamed token, and to the first content token |
| `chunk_t` | Arrival time of each streamed chunk, in seconds from send |
| `e2e_s` | Send to end of stream |
| `usage` | Engine-reported `prompt_tokens`, `completion_tokens`, cached tokens |
| `n_chunks`, `out_chars`, `reasoning_chars`, `out_sha256` | Output shape and a hash, used to detect nondeterminism |
| `finish_reason`, `error` | Errors are recorded, never retried silently |
